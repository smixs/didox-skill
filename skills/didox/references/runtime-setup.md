# Pre-flight

Проверить до начала работы. Чего-то нет → стоп, сказать пользователю, что и где взять.

## 1. Python

```bash
command -v python3 >/dev/null || echo "MISSING: python3 (3.8+)"
```

CLI — один файл на stdlib, ничего ставить не нужно.

Для подписи (`sign`/`accept`/`reject`/`cancel`) дополнительно: `uv` (мост
`eimzo_sign.py` тянет websockets через PEP 723) и запущенное приложение
E-IMZO — оно живёт на машине пользователя с ключом ЭЦП; на сервере его нет
и не будет, там доступно всё остальное:

```bash
command -v uv >/dev/null || echo "MISSING: uv (нужен только для sign)"
nc -z 127.0.0.1 64646 || echo "MISSING: E-IMZO не запущен (подпись только на машине с ключом)"
```

Для конвейера docx→PDF (`clean_docx.py` + `docx_to_pdf.sh`) дополнительно:

```bash
command -v pandoc >/dev/null || echo "MISSING: pandoc (нужен только для docx→PDF)"
command -v uv >/dev/null || echo "MISSING: uv (weasyprint ставится сам через uv run --with)"
```

Нет pandoc (голый контейнер) — конвейер недоступен; готовый PDF можно
подавать и без него, а конвертацию сделать на машине, где pandoc есть.

## 2. Конфигурация

Env-файл ищется в таком порядке: путь из `--env`, `./.env` рядом с текущей
директорией, `~/.didox/env`. Рекомендуемое место — `~/.didox/env` (chmod 600).

Обязательные переменные:

```
DIDOX_PARTNER_TOKEN=   # партнёрский JWT
DIDOX_TIN=             # ИНН компании пользователя
DIDOX_PASSWORD=        # пароль аккаунта Didox
```

Необязательные: `DIDOX_URL` (по умолчанию прод `https://api-partners.didox.uz`;
тестовый стенд — `https://testapi3.didox.uz`), `DIDOX_STATE_DIR` (кэш токена,
по умолчанию `~/.didox`).

Проверка без вывода значений:

```bash
cut -d= -f1 ~/.didox/env
```

## 3. Откуда берутся секреты (если их нет)

- **Партнёрский токен** выдаёт аккаунт-менеджер Didox: https://t.me/Didox_account,
  +998 50 122 05 18. Тестовый — на 2 месяца, боевой — по договору.
- **Пароль аккаунта** пользователь задаёт сам: didox.uz → Профиль → Аккаунт →
  поля «Пароль» / «Повторите пароль» (минимум 8 символов, буква + цифра +
  спецсимвол). Вход по ЭЦП пароля не создаёт — у пользователя, который всегда
  входил по ключу, пароля нет, пока он его не задаст.
- Пароль и токен пользователь кладёт в env-файл сам; в чат их не запрашивать.

## 4. Живость доступа

```bash
scripts/didox.py login
```

Ответ `{"ok": true, …}` — работаем. `Incorrect login` — пароль не задан или
сменился (см. п. 3). `401` с текстом про partner token — токен протух или не
тот стенд (`DIDOX_URL`).
