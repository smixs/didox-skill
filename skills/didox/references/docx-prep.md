# Подготовка docx → чистый PDF

## Посчитать правки и комментарии

```bash
for f in *.docx; do
  echo "== $f"
  unzip -p "$f" word/document.xml | grep -o '<w:ins \|<w:del \|<w:commentRangeStart\|<w:moveFrom \|<w:moveTo ' | sort | uniq -c
  unzip -l "$f" | grep -c 'word/comments' || true
done
```

Нули везде — документ уже чистый, шаг чистки пропустить.

## Прочитать комментарии до чистки

```bash
unzip -p "$f" word/comments.xml | sed -e 's/<w:p[ >]/\n&/g' | sed -e 's/<[^>]*>//g' | grep -v '^\s*$'
```

Зачем: в комментариях юрист объясняет, почему пункт в такой редакции (лимит ответственности, IP на наработки, «подписать через ЭДО»). Это контекст для проверки реквизитов и для ответа пользователю, если он спросит «а что там было». После `clean_docx.py` комментарии исчезают безвозвратно.

## Принять правки, убрать комментарии

```bash
uv run --no-project scripts/clean_docx.py "<in.docx>" "<out_dir>/<name>_clean.docx"
```

Что делает: разворачивает `w:ins` (принять вставки), удаляет `w:del` и `w:moveFrom` (принять удаления), убирает `*PrChange` (принять смену форматирования), удаляет `commentRange*`, `commentReference`, все части `word/comments*.xml`, их relationships и content-types, снимает `w:trackRevisions` в settings. Затем сам себя проверяет и падает, если в результате остались `w:ins`/`w:del`/комментарии.

Не «принимать правки» через Word GUI/AppleScript: скрипт детерминированный и оставляет след в stdout, который можно показать пользователю.

## Прочитать текст

```bash
pandoc "<clean.docx>" -t plain --wrap=none -o "<clean.txt>"
```

Реквизиты — раздел «РЕКВИЗИТЫ И ПОДПИСИ СТОРОН» (в договорах РУз обычно последний). Там ИНН, р/с, МФО, адрес обеих сторон. Сумма и НДС — раздел «Стоимость услуг и порядок расчётов». Порядок актов через ЭДО — там же (п. «Акт считается полученным при направлении через оператора ЭДО»).

## docx → PDF

```bash
scripts/docx_to_pdf.sh "<clean.docx>" "<out_dir>/<Latin_name>.pdf"
```

Внутри: `pandoc -s -t html5` (docx → HTML) → CSS для A4/Times 11pt/таблицы с рамками → `weasyprint` (HTML → PDF) через `uv run --with weasyprint --with pypdf`; число страниц считает pypdf. Всё в фоне, ни одного окна.

Почему не Word: `osascript` к Microsoft Word работает, но каждый запуск поднимает GUI и macOS просит у пользователя доступ к папке с файлом — пользователь явно против («программно, без Word»). LibreOffice не установлен и ставить его ради одного договора не надо. Headless Chrome (`--print-to-pdf`) в этой среде виснет на сетевых хендшейках — тупик.

Что теряется в pandoc-рендере и с чем смириться: таблицы без рамок в Word (блок подписей) получают рамки; выравнивание по центру у шапки заменяется стилями `h1/h2`. Юридический текст, нумерация пунктов, таблицы реквизитов и графиков — без потерь. Если пользователь требует пиксельную копию Word — он конвертирует сам.

Кириллица в имени файла работает, но в списке Didox и в `file_upload` латиница надёжнее и читается однозначно.

## Проверка PDF глазами

`Read` PDF с `pages` (первая, страница с суммой, последняя с реквизитами). Что искать: зачёркнутый/подчёркнутый цветной текст (остатки правок), выноски на полях (комментарии), «___» в датах у акта (значит акт — шаблон, подавать рано).
