# API: справочники и маршруты

Значения ниже сняты с боевого API 21.08.2026 (наблюдённые данные реальных
документов, не копия документации). Официальная документация:
https://api-docs.didox.uz — при расхождении верить живому API и обновить
этот файл.

## Подтипы произвольного документа (000)

| Код | Подтип | Когда |
|---|---|---|
| 2 | Письмо | сопроводительные письма |
| 3 | Договор | сам договор |
| 5 | Акт выполненных работ | акты сдачи-приёмки услуг |
| 6 | Другое | всё, что не легло в остальные |
| 8 | Спецификация | перечень товаров/цен |
| 9 | Доп. соглашение | приложения к договору |

Приложения к договору — всегда 9, не 6 и не 8: юридически приложение — это
соглашение сторон, дополняющее договор; так его классифицирует бухгалтерия
контрагента (правило пришло из браузерного скилла didox после отказа от
«Другое»).

## Статусы документов (`doc_status`)

Коды зависят от типа документа. Для счетов-фактур (002/008) и произвольных (000):

| Код | Значение |
|---|---|
| 0 | черновик |
| 1 | подписан отправителем, ждёт подписи партнёра |
| 2 | ждёт вашей подписи (входящий) |
| 3 | подписан обеими сторонами |
| 4 | отказ от подписи |
| 5 | удалён |
| 50 | аннулирован налоговым комитетом |

У других типов свои серии: ТТН (041) и гибридные СФ (023) — транспортные
100/200-коды, доверенности (062) — 300-серия, у писем (031) код 3 значит
«прочитано», а не «подписан». Перед выводом о статусе нестандартного типа
сверься с карточкой документа (`doc <DOC_ID>`), не с этой таблицей.

Фильтр в списке: `docs --status <код>` (можно несколько через запятую,
`limit` ≤ 100). Черновики видны только с `--status 0` — в общей выдаче их нет.

## Payload черновика 000 (что делает draft-000 под капотом)

`POST /v1/documents/000/create`:

```json
{
  "data": {
    "Document": {"DocumentNo": "...", "DocumentDate": "YYYY-MM-DD", "DocumentName": "..."},
    "Subtype": 5,
    "ContractDoc": {"ContractNo": "...", "ContractDate": "YYYY-MM-DD"},
    "SellerTin": "...",
    "Seller": {"Name": "...", "BranchCode": "", "BranchName": "", "Address": "..."},
    "BuyerTin": "...",
    "Buyer": {"Name": "...", "BranchCode": "", "BranchName": "", "Address": "..."}
  },
  "document": "data:application/pdf;base64,<PDF>"
}
```

Ограничения: PDF ≤ 10 МБ, один файл на документ, даты `YYYY-MM-DD` (не
`дд.мм.гггг` — это формат браузерной формы, API его не принимает).

Документ 000 виден только контрагентам внутри Didox: в роуминг к другим
операторам ЭДО (Faktura.uz и др.) он не уходит. Если контрагент не в Didox —
произвольным документом его не достать.

## Маршрут «подать акт контрагенту»

1. `docs --partner <ИНН>` — найти договор со статусом 3, взять его
   `name` (номер) и `contract_date`. Ссылка в акте обязана указывать на этот
   договор: акт к номеру из локального docx, которого нет в ЭДО, контрагент
   отклонит, и подача повторится с начала.
2. Подготовить чистый PDF акта — конвейер docx→PDF описан в скилле didox
   (clean_docx, docx_to_pdf).
3. `draft-000` с `--subtype 5`, `--contract-no/--contract-date` из шага 1.
4. `docs --partner <ИНН> --status 0` — черновик появился, реквизиты верны.
5. Сообщить пользователю: подписать в кабинете didox.uz → Черновики →
   документ → «Подписать» (E-IMZO).

## Тестовые прогоны

Черновик для проверки связки — только с номером `TEST-…` и немедленным
`draft-delete` после проверки: тестовый документ с обычным номером легко
принять за рабочий и подписать.

## Полезные эндпоинты для `raw`

| Путь | Что |
|---|---|
| `GET /v2/documents?…` | список (параметры: owner, status, partner, doctype, page, limit) |
| `GET /v2/documents/statistics/all` | счётчики |
| `GET /v1/documents/{id}` | карточка |
| `GET /v1/utils/info/{tin}` | компания по ИНН из налоговой базы |
| `GET /v1/profile` | свой профиль |
| `POST /v1/documents/{doctype}/create` | создать черновик |
| `POST /v1/documents/{id}/update/{doctype}` | обновить черновик (взять JSON из карточки, поправить, отправить) |
| `POST /v1/documents/{id}/delete/draft` | удалить черновик |
| `GET /v1/profile/vatRegStatus/{tin}` | статус плательщика НДС по ИНН |
| `GET /v1/banks/all`, `/v1/regions/all`, `/v1/districts/all`, `/v1/measures/all` | справочники |

Эндпоинты подписи (`/sign`, `/tosign`, accept/reject) через `raw` не вызывать —
причина в SKILL.md, раздел «Подпись — только пользователь».
